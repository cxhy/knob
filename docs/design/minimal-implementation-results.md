# VCS 最小实现验证报告

日期：2026-11-11。目标：用真实 VCS 编译与运行验证 [可行性评估](vcs-feasibility.md) 中的核心路径。正式规格保持不变，当前结果不代表 T1～T14 全量验收。

后续规格说明：本报告与原始证据对应 [v1.0 快照](knob-spec-v1.0.md)。用户随后确认，宿主按 UVM 日志判断用例结果，VCS 非零退出码独立表示运行异常；UVM_FATAL 返回 0 不属于待修复问题。现行规格已升级为 v1.1，新增框架接入验收；本报告保留原型验证事实，不代表新增范围已完成。

## 实现与结论

已实现纯 SystemVerilog 配置库和最小 UVM sequence 示例。库提供整数/布尔登记、严格文件解析、范围检查、上下限关系检查、冻结、带类型取值与未使用项报告。示例先应用配置，再使用 VCS 原生 `randomize()` 产生受约束事务；没有自建随机数或重新播种。

VCS W-2024.09-SP1 与 UVM 1.2 已实际编译、运行。核心能力无需自行开发 DPI/VPI 插件，也没有发现需要放宽已确认合同的工具障碍。用户接入需要遵守明确顺序，见 [README](../../README.md)。

示例的事务由 sequence 打印到日志，没有 DUT、driver、时钟或 sequencer 握手。因此结果证明文件配置、sequence 执行和原生约束求解可组合工作，不证明具体协议环境已经集成。

## 验证内容

回归入口 `bash scripts/test.sh` 复用已经编译的 `simv`，内部不调用编译器。30 个场景包含 9 个正例和 21 个预期失败场景；完整结果见 [results.tsv](evidence/minimal-poc/results.tsv)，构建与检查元数据见 [summary.json](evidence/minimal-poc/summary.json)。

| 验证点 | 实际观察 |
| --- | --- |
| 修改配置后复用产物 | 配置 A 产生 12 条事务：agent0 为 8 条、agent1 为 4 条；配置 B 产生 14 条 agent0 事务，长度全部为 256，agent1 被禁用 |
| 使用位置隔离与重复启动 | 两个位置分别取值，每个位置启动两次，复用各自配置 |
| 同 seed 重放 | 相同配置、产物、环境和 seed=12345 的事务轨迹与生效配置逐行一致 |
| seed 控制随机化 | 选定 seed=54321 的轨迹与 12345 不同；不推导任意两 seed 必定不同 |
| 默认值和未使用项 | 空文件使用默认配置；`shared.unused` 被正常报告，不导致失败 |
| 数值与文件边界 | CRLF、空白、注释、十六进制、负十六进制 signed64 最小值、十进制 signed64 最大值通过 |
| seed 边界 | signed32 最小值与最大值均实际运行成功 |
| 配置错误 | 缺文件、未知键、重复键、整数上下溢、超长数字、尾随垃圾、非法布尔、范围越界和多等号均触发对应诊断 |
| 跨参数及求解错误 | min>max 在启动准备期失败；min=max=65 满足上下限关系但违反示例的偶数约束，在实际随机化时失败 |
| seed 错误 | 缺失、同值重复、非数字、signed32 越界均被拒绝 |
| 接口误用 | 就绪前读取、重复登记、冻结后登记、重新加载和类型不匹配均被拒绝 |
| 无伪成功 | 所有负例都没有事务或完成标志；运行脚本返回失败 |

最终回归前后检查 `simv` 和生成共享库的 SHA-256 不变。开发过程中为修复问题重新编译过；“编译一次多次运行”的证据针对最终这组回归，不表示开发全过程只编译过一次。

## 实测发现与处理

1. **UVM_FATAL 的进程码为 0。** 当前安装版 UVM 使用 `$finish` 终止，21 个负例的原始退出码均为 0。运行脚本联合检查原始进程码、UVM/仿真器错误和 `KNOB_DEMO_PASS` 标志，对这些负例返回 1。集成到回归平台时必须保留这种判定，不能仅看原始退出码。
2. **非法 seed 会被 VCS 默认回退。** `+ntb_random_seed=abc` 在工具层产生 warning，并提示使用 1。库随后从 UVM 命令行接口取得原始文本，拒绝该输入，在产生事务前终止。不能用 VCS 自身的解析代替产品的 seed 校验。
3. **条件字符串表达式会影响日志格式。** 直接打印 `condition ? "file" : "default"` 曾得到带前导空格的来源字段。已改成明确的 string 变量，输出稳定的 `source=file/default`。这不需要限制用户配置。
4. **沙箱影响工具访问。** 包装入口需要写安装目录临时文件，仿真需要连接许可证服务。沙箱内分别出现只读目录和许可证连接失败；经授权在沙箱外使用相同入口后编译、运行成功，没有切换工具版本或绕过包装入口。

开发回归还发现过哈希清单使用绝对/相对路径不一致的问题，两个摘要本身一致。已统一路径后重新执行完整回归。早期失败证据保留在本地 `runs/`，不把这些中间运行算作最终通过。

## 当前需要的接入规范

- test/env 在启动准备期登记完整键表并统一冻结；所有激励入口等待准备完成。
- sequence 作者使用显式逻辑位置；调用 `apply_knobs()` 后再启动或随机化，不只在 `pre_body()` 中取值。
- 配置字段保持非 `rand`，赋值目标的宽度与登记范围匹配。每次随机化检查返回值，不直接依赖默认宏的 warning 行为。
- 每次运行创建独立目录和 `knob.cfg`，提供唯一显式 seed。复现时固定产物、环境、配置、输入与随机化调用过程。

这些规范落实已有合同，不新增用户需要批准的范围限制。运行期间改变 knob 仍不支持。

## 尚未完成的范围

当前跨参数接口只提供 `require_le`，尚未提供任意用户校验回调。尚未接入真实 DUT/driver 环境，也未完成所有语法组合、非法登记默认值、所有 seed 拼写变体或每个可能调用顺序的测试。不能把当前 30 个场景等同于正式规格全部验收。

后续新增类型时，扩展 `knob_kind`、存储表示、登记/取值接口、解析与格式化分支及对应外部行为测试。当前没有提前实现其他类型。

## 复现入口与证据

在仓库根目录执行 `make compile`，再执行 `make test`。手工运行方式见 README。构建日志位于 `build/poc/compile.log`；最新完整回归目录由 `build/poc/latest-regression.txt` 指向。各运行目录保存配置、命令、原始日志、生效配置、事务轨迹及两类状态码。

本报告旁的 `evidence/minimal-poc/` 保存最终回归摘要、输入/源码/产物标识和选定轨迹。源码、脚本或工具环境改变后，这些证据仍属于本次历史版本，应重新执行受影响验证。

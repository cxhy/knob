# knob 首版接入框架规格

版本：1.1。日期：2026-11-11。依据：用户已确认的 Q1～Q21、最小实现的 VCS 实测，以及用户随后明确的「便于其他验证人员快速接入现有验证系统」目标和结果判定方式。本规格可进入框架任务拆分与实现；已有最小原型通过 30 个场景，不代表本规格全部完成。

## Problem Statement

验证人员需要调整 UVM sequence 的发包数量、布尔开关、随机包长约束等参数。如果这些值只能通过修改源码改变，就需要重新编译 VCS 仿真环境，增加 case 迭代成本。配置还需要明确区分使用位置，并支持带 seed 的随机事务复现。

其他验证人员还需要把这一能力接入自己的验证系统。仅有能运行的演示不足以支持复用：接入者应能按文档引入框架、声明可调项并连接 sequence，无需理解解析器内部实现，也无需替换已有 UVM 类层次、编译入口或仿真结果判定脚本。

## Solution

提供可复用的 knob 接入框架，包括独立库、可复用的参数声明与使用位置接入方式、启动准备接口、sequence 接入示例、编译接入材料和快速开始文档。作者为每个可调值显式接入并统一编译。之后，验证人员在各次运行目录准备专用 `knob.cfg`，通过复用同一编译产物改变仿真行为。

配置仅在启动前准备。test/env 登记合法 knob，库加载、校验并冻结生效配置，sequence 在随机化前应用这些值。配置键区分使用位置，例如 `agent0.tx.packet_count` 与 `agent1.tx.packet_count`。首版提供整数与布尔类型，并保留未来类型扩展点。

每次运行必须显式提供唯一的 VCS 原生数值 seed 参数 `+ntb_random_seed=<数值>`。knob 提供确定的约束参数，由 sequence 的原生随机化机制产生随机值。记录 seed、生效配置和事务轨迹，以验证约定条件下的复现。

首版验收环境固定为 VCS W-2024.09-SP1 与 UVM 1.2。

接入流程为：加入框架编译输入 → 声明并登记可调项 → 启动时统一加载、校验并冻结 → sequence 应用配置后随机化 → 由宿主现有脚本判定结果。UVM 日志关键字用于用例结果判定，VCS 非零退出码用于独立的运行异常判定。框架不要求 UVM_FATAL 对应非零退出码，也不要求接入者使用项目示例的运行脚本或成功标志。

## User Stories

1. 作为验证人员，我希望修改配置后复用已编译的仿真程序，以便减少 case 调参的编译次数。
2. 作为 sequence 作者，我希望显式选择可调整的参数，以便明确 knob 的接入范围。
3. 作为验证人员，我希望通过专用配置文件修改发包数量，以便控制测试规模。
4. 作为验证人员，我希望使用布尔 knob 控制行为开关，以便切换测试场景。
5. 作为验证人员，我希望为不同使用位置设置同名参数，以便独立控制多个 agent。
6. 作为 sequence 作者，我希望同一使用位置重复启动时复用配置，以便保持行为一致。
7. 作为验证人员，我希望没有填写的 knob 使用登记默认值，以便只配置需要改变的项。
8. 作为验证人员，我希望缺少配置文件时报错，以便避免误用未准备的运行环境。
9. 作为验证人员，我希望未知或拼错的配置键被拒绝，以便及时发现无效配置。
10. 作为验证人员，我希望重复键被拒绝，以便避免隐式覆盖。
11. 作为验证人员，我希望已登记且合法但未使用的项只被报告，以便复用配置而不产生误失败。
12. 作为验证人员，我希望整数支持十进制和十六进制，以便表达计数和数值边界。
13. 作为 sequence 作者，我希望为整数 knob 声明有效范围，以便阻止无意义或危险的参数。
14. 作为验证人员，我希望整数越界时报错，以便避免截断或符号变化造成意外行为。
15. 作为验证人员，我希望布尔配置采用明确字面量，以便避免隐式类型转换。
16. 作为验证人员，我希望配置文件允许空行、空白和注释，以便维护可读的 case 配置。
17. 作为环境作者，我希望提前登记合法 knob 清单，以便在产生激励前检查配置。
18. 作为环境作者，我希望能够登记跨参数检查规则，以便在启动准备期发现上下限矛盾等错误。
19. 作为 sequence 作者，我希望在随机化前取得已经校验的生效配置，以便将其用于约束。
20. 作为库使用者，我希望未就绪取值或冻结后修改时报错，以便发现接入顺序错误。
21. 作为 sequence 作者，我希望取值类型与登记类型不匹配时报错，以便避免接口误用。
22. 作为验证人员，我希望 knob 提供固定约束参数，以便继续使用原生随机化机制。
23. 作为验证人员，我希望每次显式指定仿真 seed，以便明确随机状态的来源。
24. 作为验证人员，我希望缺失、重复或非法 seed 被拒绝，以便避免隐式播种或参数歧义。
25. 作为验证人员，我希望在约定的固定条件下重放相同随机事务序列，以便复现问题。
26. 作为验证人员，我希望实际随机化失败时终止运行，以便避免伪成功或静默回退。
27. 作为验证人员，我希望保存生效值和各值来源，以便区分文件配置与默认值。
28. 作为验证人员，我希望保存编译产物标识和运行证据，以便证明调参没有触发重新编译。
29. 作为环境维护者，我希望获得最小 sequence 示例，以便将库接入现有环境。
30. 作为库维护者，我希望类型处理有明确扩展位置，以便后续增加类型而不提前实现无需求功能。
31. 作为验证人员，我希望每次运行有独立配置文件，以便并行 case 不共享可修改输入。
32. 作为接入者，我希望获得独立可编译的框架库和编译输入说明，以便将它加入现有工程。
33. 作为接入者，我希望保留现有 test、env 和 sequence 的继承关系，以便逐项接入而无需重构环境。
34. 作为 sequence 作者，我希望同一组 knob 声明可绑定到不同使用位置，以便复用默认值、类型和范围规则。
35. 作为环境作者，我希望明确知道谁汇总登记、谁加载冻结，以便避免多个组件重复初始化。
36. 作为 sequence 作者，我希望获得可直接照用的应用配置和随机化接入示例，以便避免调用顺序错误。
37. 作为环境作者，我希望能加入自己的跨参数检查，以便支持上下限比较之外的业务规则。
38. 作为接入者，我希望继续使用现有日志关键字判断用例结果，以便不改造回归平台。
39. 作为回归维护者，我希望单独保留 VCS 原始退出码，以便区分用例失败和工具运行异常。
40. 作为验证人员，我希望错误诊断指出配置键、适用的文件行号和错误类别，以便快速定位配置问题。
41. 作为接入者，我希望从一份快速开始文档完成首次配置变更运行，以便无需阅读框架内部实现。
42. 作为接入者，我希望看到独立宿主环境中的集成示例，以便确认框架不依赖演示专用类或脚本。
43. 作为维护者，我希望明确公共接口、接入顺序和类型扩展位置，以便维护框架及调用方的兼容关系。

## Implementation Decisions

以下规则是可观察合同。内部类名、源码布局和具体函数签名由实现阶段选择，必须保持这些规则。

### R1：配置来源与使用位置

- 运行时只读取 Solution 中指定的运行目录配置文件。每次运行使用独立目录和配置文件。
- 不支持命令行覆盖 knob。原生 seed 参数只控制仿真随机状态，不覆盖 knob。
- 使用位置由接入方显式提供。完整配置键由使用位置和 knob 名称组成，精确匹配且区分大小写，不支持通配符。
- 键由点分隔的非空标识段组成。每段以字母或下划线开头，后续为字母、数字或下划线。位置名是逻辑名称，不要求直接复制 UVM 对象层次。
- 不同使用位置可配置同名 knob；同一位置重复启动 sequence 复用其生效配置。

### R2：登记与类型扩展

- 接入方为每个可调值显式提供接入代码，并提前登记合法配置键、类型、默认值及整数有效范围。
- 首版仅实现整数与布尔类型。类型处理需要有明确扩展位置和接入说明；不提前实现其他类型，也不要求特定插件框架。
- 重复登记、非法默认值、默认值越界、取值类型不匹配均报错。未知键不能因未被读取而逃过配置检查。
- 参数在目标 sequence 中的接入及取值转换必须保持登记的类型和范围合同。

### R3：文件语法与数值

- 每个配置行采用键、等号和值的形式，只有一个等号，键和值均非空。忽略行首、行尾及等号两侧空白。
- 支持 LF、CRLF、空行、整行及行尾井号注释。注释不构成配置值或额外赋值。
- 整数是 64 位有符号数学数值，合法类型范围为 −2^63 至 2^63−1；还必须满足各 knob 登记的有效范围。
- 整数支持十进制及带 0x 前缀的十六进制，可带前导负号。不接受前导正号、数字分隔下划线、表达式或 SystemVerilog 宽度字面量。
- 负十六进制按负的数学数值解析；高位全为 1 的正十六进制不能隐式转换成负数。负的 0x8000000000000000 表示最小整数，正的 0xffffffffffffffff 越界。
- 布尔只接受小写 true、false，不将数字 0、1 隐式转换成布尔。
- 重复配置键、未知键、语法错误、非法值、类型或登记范围越界都必须使运行失败。
- 文件必须存在。文件中缺少某个合法 knob 时使用登记默认值；存在但为空或仅含注释的文件依照同一缺项规则处理。
- 首版不处理 include、环境变量替换或表达式。

### R4：生命周期与失败时机

- test/env 先登记清单和跨参数检查规则，再加载、校验并冻结生效配置。只有准备成功，sequence 才能取值并产生随机激励。
- 未就绪取值、冻结后新增登记、冻结后再次加载或修改配置均报错。
- 所有可在启动准备期发现的输入、登记和配置错误必须在产生激励前使运行失败。
- 接入方提供跨参数检查，例如最小值不大于最大值。此检查在发包前执行。
- 库不承诺提前证明所有未来随机化约束可满足。只能在实际求解时发现的无解，在该次随机化失败时立即使运行失败。
- 失败后不自动更换 seed 重试，不退回默认配置，也不能将失败报告为通过。
- 已登记且合法但本次未被读取的配置是正常场景。结束时以普通信息报告未使用项，不影响通过；这不改变未知键错误规则。

### R5：随机化与 seed

- knob 提供确定的约束参数，例如随机包长上下限。sequence 使用 SystemVerilog/UVM 原生随机化，knob 不自行抽样或建立独立 seed。
- sequence 必须先应用生效配置，再执行受其影响的随机化。接入不能仅依赖可能晚于随机化或被跳过的启动回调。
- 每次运行必须显式给出唯一的原生 seed 参数，其值为十进制 32 位有符号整数。缺失、重复、非数值或越界均失败；不沿用工具默认值作为产品缺省策略。
- 运行中按固定约束产生随机样本不属于动态修改 knob。配置本身在冻结后保持不变。
- 复现条件是编译产物、工具环境、配置、seed、外部输入及随机化调用过程相同。在这些条件下，随机事务序列必须一致。
- 不保证跨工具版本、修改代码或改变配置后的序列一致性，也不要求任意两个不同 seed 必然产生不同样本。

### R6：交付与可观测结果

- 首版交付可独立接入的框架库、编译输入材料、最小 sequence 示例、独立宿主接入示例、快速开始与公共接口说明、类型扩展说明，在已选定的 VCS/UVM 组合上验证。
- 保存编译和运行日志、seed、完整生效配置及每项值来源、随机事务轨迹、编译产物标识。
- 诊断必须能区分配置失败、接口使用错误、约束求解失败和正常未使用项。验收依据可观察结果，不以解析器自测或工具版本命令替代真实仿真。

### R7：框架职责与低侵入接入

- 框架核心负责声明登记、解析、类型与范围检查、跨参数校验执行、冻结、带类型读取及配置报告；宿主负责生命周期编排、业务规则、sequence 字段应用和整体仿真结果判定。框架不接管 DUT、driver 或协议行为。
- 提供框架所需的源文件清单、编译顺序、依赖版本和导入说明。宿主通过自己的编译入口引用这些材料，不要求运行项目专用脚本；可交付的库和编译材料不能依赖开发机器的绝对路径或演示源码。
- 允许通过对象组合和显式调用接入，不强制 test、env、sequence 改继承框架基类，不强制替换宿主已有 factory、sequencer 或 phase 调度体系。
- 参数声明按可复用的一组组织，包含名称、类型、默认值和范围；同一组声明可以绑定不同显式使用位置。接入者无需为每个位置复制解析器或整套登记逻辑。同一完整配置键仍只能登记一次，重复登记继续按 R2 报错。
- 宿主指定统一的启动准备入口，收集各组件的声明和检查规则后加载并冻结。框架提供可判断的就绪状态与明确的错误诊断；不会自动拦截绕过约定流程的无关激励代码。
- sequence 接入通过显式逻辑位置和公共取值接口完成。文档提供可复用的应用配置模式，保证确定的配置字段不被后续随机化覆盖；不把原型的具体类名或方法名当作固定公共 API。
- 支持接入者登记自定义、无仿真时间消耗的跨参数校验逻辑。校验逻辑读取类型化、只读的候选生效配置，在全部值解析及单项检查完成后、正式冻结和产生激励前执行；校验失败终止准备。该专用校验访问不等同于开放普通 sequence 的提前取值，不放宽 R4 的就绪前读取禁令。
- 校验逻辑不得修改配置、产生激励、抽取随机值或重新播种。公共 API 文档写明各调用的合法阶段、输入类型、值的所有权和失败行为。框架内置的上下限比较可以作为便捷规则，不能代替用户自定义检查入口。

### R8：沿用宿主结果判定

- 配置错误、接口误用和随机化无解以 UVM_FATAL 或等效的既有致命诊断终止对应流程，提供稳定且有文档说明的诊断标识。对文件输入问题提供适用的配置键和行号，对接口问题提供操作与状态信息。
- 宿主脚本按既有 UVM 日志关键字规则判断用例是否通过。UVM_FATAL 终止后的 VCS 原始退出码可以为 0，这符合接入合同，不作为框架缺陷，也不要求通过额外退出机制把它改成非零。
- VCS 原始非零退出码独立归入运行异常并保留原值，不把它自动解释为某个 knob 配置错误。日志失败与运行异常可以分别记录；框架不规定宿主平台的具体状态码或优先级。
- 正常未使用项不使用错误或致命级别，避免被宿主日志规则误判失败。框架诊断采用独立标识，方便宿主定位问题。
- 示例运行脚本、原型的汇总返回值和成功标志只服务于项目自测，不构成宿主接入依赖。整体测试通过由宿主决定，框架加载成功不等同于整个仿真用例通过。

### R9：快速开始与接入材料

- 快速开始覆盖引入编译输入、登记一个整数和一个布尔项、准备配置文件、显式 seed 运行、修改配置后复用产物，以及定位一个错误配置。步骤应列出必要改动和可核对的结果。
- 提供参数声明复用、多个使用位置、缺省值、用户跨参数校验、sequence 与 item 随机化前应用参数的示例。说明已有基类和启动方式如何保留；对需要接入者保证的调用顺序给出明确要求。
- 提供一个独立宿主 UVM 环境的接入示例。它拥有自己的 test/env/sequence 组织和编译、运行入口，复用框架公共接口，不依赖原型演示专用类或修改框架源码。
- 将「快速」落实为可照文档完成、改动位置明确、保留宿主流程并有可观察结果的验收，不设未经实测的分钟数或代码行数承诺。

## Testing Decisions

测试边界已由用户在 Q21 确认：以一次编译得到的仿真程序为入口，在不同运行目录提供配置文件和 seed，检查运行结果、诊断与事务轨迹。使用最小 UVM 环境从外部行为覆盖库的登记、解析、校验、冻结、读取、sequence 约束接入与诊断，不依赖内部数据结构断言。

当前仓库已有最小库、UVM sequence 示例和 30 场景回归，可作为先例并继续复用。该回归已经证明核心链路可运行，但不覆盖全部规格，也不等同于独立宿主快速接入验收。新增宿主接入用例仍沿用相同最高边界：编译后的宿主仿真程序接受配置和 seed，由宿主日志判定及事务结果验证；不新增依赖内部数据结构的验收边界。必要的内部定位检查可以辅助调试，但不能替代以下验收。

| T1 | 编译一次，多配置运行 | 修改发包数量、布尔开关和包长约束后行为符合配置，编译产物标识不变，无新增编译 | R1、R3、R6 |

| T7 | 生命周期错误 | 未就绪读取、冻结后登记/加载/修改均失败 | R4 |
| T8 | 跨参数矛盾 | 接入方规则检测到上下限矛盾，并在发包前使运行失败 | R4 |
| T9 | 实际约束无解 | 强制无解用例在随机化失败处终止，不换 seed、重试、退默认或伪报通过 | R4、R5 |
| T10 | seed 输入错误 | 缺失、重复、非十进制数值、32 位范围外 seed 均失败 | R5 |

| T13 | 证据完整 | 日志、seed、生效值与来源、轨迹及产物标识足以核对无需重新编译和复现 | R6 |

| T15 | 独立宿主编译接入 | 按交付清单在另一工程目录通过宿主编译入口引入框架；无需开发机器绝对路径、演示专用类或修改框架源码，保留宿主类继承关系并完成运行 | R6、R7 |
| T16 | 声明组复用 | 同一声明组接入两个使用位置，配置独立生效，默认值/范围一致；同一完整键重复登记仍被拒绝 | R2、R7 |
| T17 | 用户自定义校验 | 宿主通过公共入口登记一条内置上下限比较之外的确定性规则；有效配置运行，非法组合在零事务时以对应诊断失败；普通提前读取仍失败 | R4、R7 |
| T18 | 宿主判定兼容 | 宿主沿用日志规则识别 UVM_FATAL 负例，即使原始进程码为 0 仍判用例失败；非零原始码独立记录为运行异常，正常 unused 不误报；无需原型成功标志 | R6、R8 |
| T19 | 快速开始可执行 | 按文档在独立宿主完成引入、登记、首次运行、换配置复用产物和错误定位；必要文件、调用位置和预期结果齐备，调用方不需阅读或修改框架内部实现 | R6、R7、R9 |

所有错误场景均检查实际用例判定及对应诊断，并独立记录原始进程结果。配置失败不要求 VCS 原始退出码非零；运行异常也不能充当指定配置错误已被正确发现的证据。对能够在启动准备期发现的错误，还检查失败前没有产生激励。动态求解失败按实际失败点检查，不倒推成启动期保证。

## Out of Scope

- 永久排除仿真运行中动态修改 knob。
- 首版不支持命令行覆盖 knob、通配符匹配、自动发现任意 sequence 字段或不显式接入的参数改写。
- 首版不支持整数和布尔以外的值类型，也不提供配置表达式、文件 include 或环境变量展开。
- 不实现独立随机数发生器、独立 seed 或失败后自动换 seed 重试。
- 不保证跨版本、修改代码或配置之后的随机序列仍相同，不保证所有不同 seed 的输出互异。
- 首版不承诺已选 VCS/UVM 组合之外的兼容性。
- 不建设或替换宿主回归平台、日志关键字判定系统、DUT、driver 或协议库，不将项目本机工具包装脚本作为框架使用条件。
- 不要求通过修改 VCS 退出行为解决 UVM_FATAL 返回 0，不强制接入者使用原型的成功标志或汇总退出码。

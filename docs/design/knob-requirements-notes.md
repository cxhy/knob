# knob 需求访谈记录

本文件保留 `grill-with-docs` 的需求确认过程。用户于 2026-11-11 确认 Q1～Q21 与整体共同理解，访谈任务为 `knob-4ys`。正式规格见 [knob-spec.md](knob-spec.md)；本记录不代替产品实现或运行验证。

后续确认（2026-11-11）：最小实现通过真实 VCS 编译与 30 场景回归后，用户要求推进 `to-spec`，建立便于其他验证人员快速接入既有验证系统的框架。用户明确，现有仿真脚本通过 UVM 日志关键字判断用例结果，VCS 非零退出码代表另一类运行问题；UVM_FATAL 原始返回 0 不构成障碍。规格 v1.1 保留 Q1～Q21，补充可复用接入交付及结果分层，继续沿用 Q21 已确认的最高验收边界。

## 已确认范围

仅在每次启动仿真前确定配置，永久排除运行中动态调参，见 ADR-0001。目标为 UVM 组件相关 sequence 的可配置参数，例如发送数据包数量；每个可调值显式接入后统一编译，配置仅来自专用文件，暂不支持命令行覆盖，见 ADR-0002。

## 第二轮确认（2026-11-11，Q4～Q7）

- 同一种 sequence 在不同使用位置分别配置；例如 `agent0` 与 `agent1` 可以使用不同发包数量。
- 配置文件必须存在。未填写的 knob 使用接入代码中的默认值。
- 配置中的非法值或拼错的参数名应报错，并使本次仿真失败。
- 第一版仅支持整数和布尔类型，同时须为未来增加其他类型保留扩展点。当前不实现其他类型。
- 每次仿真固定读取当前运行目录的 `knob.cfg`。每次运行使用自己的目录和配置文件，避免并行 case 共用可修改文件。

## 第三轮确认（2026-11-11，Q8～Q12）

- 使用位置由接入代码显式提供，完整键采用类似 `agent0.tx.packet_count` 的组成方式。第一版精确匹配，不支持通配符。同一使用位置重复启动 sequence 复用配置；需要不同配置时使用不同位置名。
- 整数为 64 位有符号整数，支持十进制和 `0x` 十六进制；每个 knob 声明有效范围，超出类型范围或声明范围时报错。
- 文件每行采用 `配置键 = 值`，允许空行和 `#` 注释。布尔值使用 `true`、`false`。同一键重复出现时报错。
- 在任何 sequence 发包前完成配置检查。接入方提前提供合法 knob 清单，不能仅在 sequence 执行到取值点时才发现未知配置键。
- 第一版必须支持随机化约束需求。随机数必须由仿真启动时输入的 seed 统一控制，并满足可复现要求。具体分工与复现条件在第四轮确认。

运行中按固定配置进行随机采样属于正常仿真行为，不等于在运行中动态修改 knob 配置；ADR-0001 的永久边界仍有效。

## 第四轮确认（2026-11-11，Q13～Q15）

- knob 提供确定的约束参数，例如包长上下限；sequence 使用 SystemVerilog/UVM 原生 `randomize()` 产生随机值。knob 系统自身不抽取随机值。
- seed 统一通过 VCS 原生运行参数 `+ntb_random_seed=<数值>` 提供。每次必须显式指定数值 seed，遗漏时报错。knob 系统不另设独立 seed；seed 用于仿真随机状态控制，不覆盖 `knob.cfg` 中的参数。
- 复现验收固定相同编译产物、工具环境、配置、seed、外部输入与随机化调用过程，要求随机事务序列一致。
- 记录 seed 与最终生效配置以支持重跑。跨工具版本、代码修改或配置变化后的随机序列一致性不纳入保证。

该组决定见 ADR-0003；接口事实核查见 `randomization-evidence.md`，尚无编译或仿真实测。

## 第五轮确认（2026-11-11，Q16～Q19）

- test/env 提前登记合法 knob，加载并校验配置，再冻结配置；sequence 应用配置后再执行 `randomize()`。未就绪时取值、冻结后新增登记均报错，见 ADR-0004。
- 已登记且合法的配置项可以在本次没有被读取。用户说明这是正常情况，包括验证人员未清理配置或复用配置；结束时报告未使用，不使仿真失败。报告采用普通信息，不把未使用等同于未知键。未知键仍按已有规则报错。
- 接入方提供跨参数检查规则，例如 `min <= max`，在发包前检查。只能在实际 `randomize()` 时发现的约束无解，立即使本次仿真失败；不换 seed 重试、不退回默认值。启动校验不承诺证明所有未来随机化求解都可满足。
- 首版固定 VCS W-2024.09-SP1 与 UVM 1.2，交付可接入现有环境的库及最小 sequence 示例。真实编译、配置检查和 seed 复现验证在该组合完成。

## 最终汇总确认（2026-11-11，Q20～Q21）

Q20：用户已采纳以下语法与输入边界。

- 配置键区分大小写，以点分隔非空标识段；每段采用字母或下划线开头、后续字母/数字/下划线。位置名为显式逻辑名称，不要求直接复制 UVM 层次路径。
- 忽略行首行尾和等号两侧空白；支持 LF、CRLF、空行、整行及行尾 `#` 注释。一个配置行仅有一个等号，键和值不可为空。
- 整数可带前导负号，十进制或 `0x` 十六进制均按数学数值解析；范围为 `-2^63` 至 `2^63-1`。例如 `-0x8000000000000000` 是最小值，`0xffffffffffffffff` 越界，不隐式转成 `-1`。不接受数字分隔下划线、正号、表达式或 SystemVerilog 宽度字面量。
- 布尔只接受小写 `true`、`false`，不把 `0`、`1` 隐式转换成布尔。
- 文件只提供字面量，首版不处理 include、环境变量替换或表达式。
- seed 参数必须唯一、显式且为十进制 32 位有符号整数；缺失、重复、非数值或越界均失败。该输入范围与 64 位 knob 整数区分。
- 登记键重复、默认值非法、默认值或覆盖值越界、取值类型与登记类型不匹配均报错。冻结后再次加载或修改配置也报错。

Q21：用户已采纳以下首版验收组合，并确认整体共同理解。

- 编译一次，后续更改 `knob.cfg` 的发包数量、布尔开关、包长约束后重跑，编译产物不变且行为符合配置。
- 两个使用位置具有同名 knob，可独立控制；同位置重复启动复用生效配置。缺项使用默认值；合法未使用项只报告。
- 对比相同配置与 seed 的两次运行，随机事务序列一致；选定不同 seed 的案例证明随机化受 seed 影响，不要求任意两个 seed 都产生不同输出。
- 覆盖整数和布尔边界、重复或未知键、缺文件/seed、非法登记/取值/生命周期调用，以及接入方跨参数校验。可以在启动准备期发现的失败必须发生在产生激励前。
- 强制无解案例在 `randomize()` 失败时终止，不输出伪成功、不变更 seed 重试或回退默认值。
- 保存编译与运行日志、seed、完整生效配置及值来源（文件或默认）、随机事务轨迹和编译产物标识，支持核对未重新编译及复现。
- 类型扩展在接口设计中给出具体扩展位置与接入说明；首版不提前实现额外类型。

本节已获用户批准。新增类型的扩展要求不指定某种具体接口或插件机制；实现可以选择满足该要求的内部结构。

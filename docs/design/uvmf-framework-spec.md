# UVMF 公共验证框架首版规格

spec_id：`uvmf-framework-v1`。版本：1.2。日期：2026-11-11。

本规格汇总用户已确认的 Q1～Q27 及后续澄清，作为第二阶段实现与验收基线。规格定稿表示需求已收敛，不表示公共框架已实现或产品验收通过。第一阶段 [knob v1.2 规格](knob-spec.md) 继续定义配置库合同；本规格不替换其接口、类型、seed 或错误规则。

## 目标与交付

降低新模块验证环境的部署难度，让熟悉 SystemVerilog/UVM、尚不熟悉 UVMF 的 DV 能通过统一入口建立工程，并按基础验证流程补充模块业务。DV 可增加、替换或删减流程步骤，无需为跳过步骤申请批准。

首版交付公共依赖与版本引用机制、初始化及生成/再生成/编译/运行/回归入口、明确的业务扩展位置、RTL 与文档驱动的 DUT 连线过程、可选 knob 模板、完整 ALU 示例及使用说明。首版完成点为 M5 的 DV 自助使用验收；真实项目试点属于后续 M6。

## 输入、产物与责任

| 类别 | 内容 | 责任 |
| --- | --- | --- |
| 环境描述 | 带说明的 UVMF 原生 YAML 模板；接口、事务、agent、环境和 test 关系 | 框架提供模板，DV 填写并扩展 |
| 工程配置 | DUT/仿真顶层、设计 filelist、路径基准、宏/include 等编译上下文及公共版本引用 | 框架提供入口，DV 按设计交付配置 |
| 设计输入 | RTL、设计 filelist、端口语义、时钟/复位及连接要求的设计文档 | 设计侧交付并澄清矛盾或缺失 |
| 业务代码 | 协议驱动与采样、业务激励、参考模型/检查和覆盖目标 | DV 编写或复用已有资产 |
| 连线产物 | 可编辑映射、RTL/文档来源、生成的 DUT 连接及未解决项 | 框架协助推导，DV 可修订映射 |
| 工程产物 | 生成骨架、手写扩展、版本记录、独立编译和运行入口 | 框架组织结构，项目保存自身代码 |

设计 filelist 直接引用，不要求设计项目调整目录。入口必须明确其路径求值基准，并使 RTL 查询与实际编译使用的顶层、宏和 include 上下文可核对；无法处理的选项给出具体诊断，不声称支持任意 filelist。具体文件格式和命令名由实现设计确定。

## 行为要求

### F1：基础工程独立可用

基础 UVMF 工程必须能在没有 knob 库、`knob.f` 和 `knob.cfg` 的情况下生成、编译、运行与自动检查。选择可选增强后才引入对应依赖和接入代码；业务逻辑不依赖 knob 是否启用才能维护。

### F2：统一入口与编译运行分离

提供初始化、生成/再生成、单独编译、单次运行和回归的统一入口，并保留项目侧扩展能力。运行入口复用已有编译产物，不隐式重新编译；需要重编译时明确提示。每次运行独立保存配置、seed 和日志，不能共享可修改的运行目录。

### F3：公共依赖与版本

公共发布内容包括三个独立版本：UVMF 上游包（基础 SV 库、生成器、模板及随包 Python 依赖）、我们维护的公共框架入口/模板/适配，以及可选 knob 库和编译接入材料。它们各自记录版本，不强制使用相同版本号。Python/uv、Node、VCS/UVM 和 hdl-kgraph/xverif 属于外部工具环境，记录必要入口及版本，不复制安装目录进入公共包。RTL/filelist、项目 YAML、业务代码、连线映射、knob.cfg 及生成/运行产物归项目保存。此范围已由用户在公共依赖讨论后确认。

公共依赖统一部署在 workspace 下的版本目录；项目记录版本与内容标识，并通过配置定位依赖。已发布公共版本保持不变，不通过可变 latest 引用使旧项目自动升级。项目主动选择新版本并执行受影响检查，旧版本可继续引用以便回退。

项目差异优先在项目扩展处理；共性改进由框架维护者形成新版本。具体 workspace 子目录、版本记录格式和发布命令由实现选择，本规格不授权覆盖已有公共安装。

### F4：离线日常使用与工具环境

新环境 checkout 本项目后，必须可通过仓库内入口向调用者指定目录准备公共版本，不依赖开发机的旧共享目录、build 缓存或 Git 标签。部署所需入口和固定输入记录必须随源码交付；UVMF 作为显式外部输入提供固定归档或匹配的解包目录，不暗中下载。纯复制部署的前置条件与生成/编译/运行所需工具分开说明。错误输入、来源校验失败和正常已有版本冲突应在写入目标前失败；不将未提交的工作区或候选源码测试报告为远端已可 checkout。

公共准备阶段集中取得并核对所需依赖；准备完成后，项目生成、编译和运行不临时联网下载。Python 按项目约定通过 uv 管理，登记解释器与锁定依赖。依赖缺失时报告缺口，不悄悄联网或切换版本。

首版以当前 VCS W-2024.09-SP1 / UVM 1.2 作为验收环境，保留可配置的工具路径和适配入口。不扩大兼容矩阵，不把假设性兼容差异作为前置问题；实际差异出现时再处理并记录。工具失效不等于产品通过，也不阻止独立的文档或静态工作。

### F5：持续再生成与业务扩展

明确生成文件、可保留 custom 区块与独立手写文件的位置。支持持续再生成；验证工程与手写代码的合并冲突由 DV 修复。只承诺已说明的保留机制，不承诺任意位置的手工修改自动保留。

首版必须验证相同 YAML 再生成及一次代表性接口或配置字段增量变更。记录生成前后差异、保留的业务代码、必要的 DV 修复，以及重编译后的运行结果。具体字段由实施阶段选择。

### F6：RTL 查询与 DUT 连线

使用 `hdl-kgraph` 查询 RTL 模块、层级、端口和连接信息，并结合设计交付文档推导 DUT 连线。保存可编辑映射及其 RTL/文档来源，供 DV 修订和后续再生成使用；输入变化后核对受影响连接。

解析到端口不等于确定设计语义。文档与 RTL 矛盾、设计信息缺失反馈设计侧澄清；存在未解决的必需连接时，不报告完整连线通过。参数表达式不能当作已求值位宽。具体映射格式、诊断实现及生成组织由实现选择，不要求任意冲突自动修复。

当前没有真实 RTL 时缺项目图不阻塞规格设计；实施示例连线时需按示例的 filelist 和编译上下文建立其项目图并验证实际查询，不复用其他工程图。服务登记或最小握手不替代真实示例连线验收。

### F7：可选 knob 生命周期

提供统一初始化模板和典型整数/布尔参数示例，由 DV 显式声明和应用；首版不从 YAML 批量生成任意字段接入。保留启动时登记、加载校验冻结、使用前应用的顺序。

参与约束的值必须在每次受影响求解前应用，并保证最终使用值不被随机化或 initialize 覆盖。后创建对象取得已准备的位置句柄，冻结后不能重新登记。具体回调由实现选择，不强制所有宿主改继承关系。

knob 不创建独立 seed。启用 knob 时每次运行提供唯一合法的 `+ntb_random_seed`，缺失、重复或非法输入按 v1.2 合同失败。固定产物、环境、配置、seed、外部输入和调用过程时可重放；不要求与接入前或跨构建轨迹相同。

Q19 已经定向 ALU 实测，不再设置独立前置大实验阻塞实施。公共入口接入后的配置生效、重放和失败行为仍须实际验收；现有实验只支持它记录的字段和流程。

### F8：结果与诊断

允许业务逻辑未补齐时执行骨架编译及基础冒烟，但输出必须说明属于骨架检查，不能据此报告 DUT 功能通过。功能通过须有实际激励与检查依据；框架不承诺自动判断任意业务逻辑是否完整。

结果共同核对原始退出码、UVM 诊断和事务轨迹。指定失败用例须证明指定错误发生；VCS 非零码独立作为运行异常。UVM_FATAL 原始码可以为 0；宿主的零事务错误不能因为 knob 关闭了请求而被吞掉或报告功能通过。

### F9：模板与基础流程

项目和团队可以增加场景模板，无需修改框架核心，并逐步积累为共享模板。基础流程覆盖模块信息与验证计划起点、环境部署、基础用例和结果检查，同时保留 DV 自由增减的能力。首版提供扩展入口和示例，不要求立即建立完整场景库或固定模块分类体系。

### F10：完整示例与交付

沿用 ALU 作为首版教学及回归示例，通过新公共入口重新完成从输入到运行、检查、再生成和可选 knob 接入的过程。必须保留无 knob 正例及错误注入检查，证明检查器能够识别错误。

说明文档覆盖依赖准备、项目起步、手写扩展、连线映射、编译运行、结果判断、换配置复用产物及问题定位。由另一位懂 UVM 的 DV 按文档独立跑通示例并开始接入新模块，记录人工步骤和反馈；agent 自测不能代替该使用者证据。

## 验收合同

验收以 [第二阶段验收矩阵](uvmf-framework-acceptance.md) A01～A16 为准，每项关联输入、版本和实际证据。M3 覆盖基础部署与维护，M4 覆盖完整示例及可选增强，M5 覆盖自助交付。未执行项目明确标为未验证；旧实验的有限通过不能自动转为公共框架通过。

## 范围外

- 存量成熟环境自动迁移、当前 CHI 改造及真实项目功能验收。
- 自动从 RTL/规格推导完整协议行为、参考模型、业务场景和覆盖目标。
- 任意 YAML/跨版本修改无冲突合并、任意设计语义矛盾自动解决。
- 完整验证 pattern 库、完整常见业务模板库及多仿真器兼容矩阵。
- 第一阶段已排除的运行中动态配置、命令行覆盖 knob、自动字段发现和独立随机数系统。

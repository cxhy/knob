# 第二阶段 milestone：UVMF 新环境部署与 knob 接入

日期：2026-11-11。状态：全部访谈与 Q19 定向确认已完成，用户授权继续规格定稿与实施拆分；当前正式行为基线为 [公共框架规格 1.2](uvmf-framework-spec.md) 和 [验收矩阵](uvmf-framework-acceptance.md)。稳定 knob 基线：`v1.2.0`（`8847bc7`）。

目标是降低新模块验证环境的部署难度，并通过可增减、可扩展的基础流程减少验证初期的思考负担。使用者熟悉 SystemVerilog/UVM，但不要求有 UVMF 经验。完整目标与职责分工见 [Q1～Q8 访谈记录](phase2-goals-interview.md)。

首版交付环境部署入口、基础流程说明和完整可运行示例。框架提供公共结构、工具入口、可选 knob 接入和扩展位置；DV 提供接口连接及模块相关的协议行为、激励、参考模型/检查规则和覆盖目标。无 knob 时也应能完成生成、编译、仿真与自动检查。流程和后续业务模板均应保留 DV 自行增减的自由。

接入、部署和验收取舍已汇总为正式规格 F1～F10 和验收 A01～A16；实施任务已在 Beads 建立依赖。M1 的完成不等于 M3～M5 通过，现有 ALU 实验不能直接作为公共入口验收。实时状态从 Beads 地图子事项读取，不在文档复制待办状态。

官方文档或公开源码只能支持其对应版本和范围的结论；不能替代当前 VCS 的实际编译运行。资料无法证明的兼容性、初始化时序或再生成行为，必须明确保留为实验问题。

发行包来源、接收位置与包内核查步骤见 [发行包设计输入准备](uvmf-package-intake.md)。

## 首版边界

- 优先新模块和新环境，存量环境迁移暂缓。
- UVMF 基础能力独立可用，knob 是可选增强；保留无 knob 的编译、运行和功能检查路径。
- 基础验证流程可由 DV 增减和扩展，不引入强制业务流程、跳过审批或固定模块分类体系。
- 协议类似组件的验证 pattern 和常见业务详细模板属于低优先级演进，不阻塞首版。
- 不自动从 RTL/规格推导完整验证逻辑；示例通过不等于任意 DUT 功能验证完成。
- 保留文件配置、显式接入、启动时冻结、原生 seed 和日志/进程结果分层等现行 [knob 合同](knob-spec.md)。
- CHI 隔离快照仅是后续候选材料，当前不推进；任何实验不得影响原项目，见 [隔离记录](phase2-chi-pilot-isolation.md)。

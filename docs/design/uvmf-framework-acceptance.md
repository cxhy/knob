# 第二阶段验收矩阵

日期：2026-11-11。依据：[正式规格 1.2](uvmf-framework-spec.md)，spec_id：`uvmf-framework-v1`。

本文定义验收标准，不维护第二套任务状态。实时执行状态与阻塞由 Beads 管理；通过证据写入对应版本报告。当前实验只作为设计依据，以下公共框架验收均需其自己的证据。

| 编号 | 要求 | 可观察通过依据 | 阶段 |
| --- | --- | --- | --- |
| A01 | F3/F4 公共部署及引用 | 干净 checkout 通过仓库入口部署到指定目录，显式提供已核对UVMF输入和必要工具；无旧目录/缓存/标签依赖，所需源码已交付；从该版本目录初始化新项目，版本/内容标识和实际引用一致 | M3 |
| A02 | F4 离线准备 | 公共依赖准备后，在禁止联网下载条件下完成新项目生成、编译和运行；缺依赖有具体错误 | M3 |
| A03 | F1 独立路径 | 编译输入不含 knob 库，运行不含 knob.cfg，ALU 实际事务与检查通过 | M3 |
| A04 | F2 独立编译/运行 | 单独编译后多次运行；记录并比对 simv/共享库标识，运行未触发编译且目录隔离 | M3 |
| A05 | F2/F5 业务扩展 | 通过项目扩展增加业务代码并运行；操作无需修改公共核心或学习内部生成脚本 | M3 |
| A06 | F5 相同输入再生成 | 明确检查 custom/独立手写文件的保留结果，重新编译后原业务检查仍有效 | M3 |
| A07 | F5 增量再生成 | 一次代表性 YAML 接口或配置字段变化，记录业务保留及必要冲突修复，重编译后运行通过 | M3 |
| A08 | F6 连线 | 对示例实际调用 hdl-kgraph，记录 filelist/宏/include/顶层、RTL和文档来源及可编辑映射；生成连接编译并运行 | M3 |
| A09 | F6 不确定信息 | 选定文档/RTL矛盾或缺失输入，明确列为设计侧澄清项，不猜连接或报告完整连线通过 | M3 |
| A10 | F3 版本升级回退 | 项目主动切换两个可识别公共版本并回退，引用和产物对应目标版本，旧项目不被隐式升级 | M3 |
| A11 | F7 换配置 | 同一产物换 knob 文件，选定整数/布尔项影响实际行为；若宿主策略报错则如实判失败 | M4 |
| A12 | F7 随机化和重放 | 配置在每次受影响求解前生效且最终未被覆盖；同 seed 固定条件轨迹一致；选定不同 seed 案例体现随机状态影响 | M4 |
| A13 | F7/F8 失败检查 | 未知键、非法配置、缺失/重复seed、实际无解等受影响合同负例出现指定诊断；启动错误在激励前失败，无重试回退；记录原始码 | M4 |
| A14 | F8/F10 检查有效 | 无 knob 正例有实际匹配；隔离错误注入产生预期 mismatch/UVM_ERROR；骨架运行不被当成功能PASS | M4 |
| A15 | F9/F10 可扩展文档 | 文档说明可增减流程、项目/团队模板扩展及业务职责；按入口完成示例、再生成、换配置和错误定位 | M5 |
| A16 | F10 DV 自助 | 另一位懂UVM的DV按文档独立跑通并开始新模块接入，保留使用者身份或角色、步骤、反馈和未解决问题 | M5 |

证据至少包含：输入与代码版本、依赖/工具版本、配置、seed、实际命令、编译与运行日志、原始进程结果、UVM诊断、适用的事务轨迹、产物标识和限制。可复用未改输入的有效证据，但新公共入口和发生变化的路径必须补验。

第一阶段 knob v1.2 的 T1～T21 继续适用；不要求无变更时机械重跑全库回归。公共集成按受影响合同选择负例并记录映射，不能用源代码阅读或自测替代实际 VCS 验收。
